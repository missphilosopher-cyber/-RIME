# Demonstrate the source-code workflow

Start the local app using README.md. Use synthetic programs for the demonstration.

## Visual introduction

Use Source and Your language to explore the illustration. Verify recovery calls Python and mirrors its real result in the opening. Pause motion to hold the illustration still. Explore the process shows actual source and mapping layers; Open workbench goes directly to the working tool. Explain that animation presents the process while Python performs it.

## Creator: define and transform

1. Open Creator mode. The P02 condition fixture and ASCII tokens load by default.
2. Name the definition and choose a family/policy. Generate three candidates and select one.
3. Inspect source, framed representation and token mapping. Edit an alias, apply it, lock it, and regenerate to show that it is retained.
4. Choose Test recovery. Show exact source recovery and Python AST equality. Explain that the program was parsed, not executed.
5. Switch to Names & operators, generate again and point out the visible number/string literals. Full-token mode also maps those categories; layout remains visible in either case.

## Builder: formalise an existing code language

1. Download the current private definition as JSON or CSV. Select Builder and import it again to demonstrate portability.
2. Refine its aliases. Deliberately assign two source units the same alias; Apply changes should reject the ambiguity.
3. Assign a custom symbol to a source token using Design sign, or upload a notation sheet, crop a symbol, and label its meaning. Apply changes and inspect the rendering.
4. Explain that pictures are display forms; the framed `.prime` representation carries the exact digital token sequence. The system does not infer unknown symbol meanings.
5. Export the `.prime` document separately from its private definition. Reopen it with the matching key and verify recovery.

## Validation and analysis

1. Append a blank line to the disguised document while keeping the header intact.
2. Test recovery. The recovered program remains syntactically valid but no longer matches the original characters exactly. The app should report the first difference.
3. Re-transform the source to restore the original document.
4. Paste `import os` and generate to show the explicit subset error. Load a supported fixture and generate again.
5. Run the experiment with three repetitions: 180 supported-input trials and 54 separate expected-error trials, 234 total.
6. Download the measured CSV and charts. Discuss conversion cost, representation size and visible patterns; do not describe them as security-strength measurements.

## Suggested introduction

“ΠRIME is a local custom code-language workbench for application-security researchers. A user can create a token language or import an existing notation, apply it to supported Python source, inspect what it reveals, and verify exact restoration.”

## Boundaries to explain

The prototype implements reversible source representation, not a production protection runtime. Uploaded programs are not executed. Other programming languages, arbitrary grammar import and runnable transformed applications need further work. Custom notation is not secure encryption, and adoption by professional users has not yet been validated.
